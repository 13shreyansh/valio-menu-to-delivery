# Judge's review (condensed copy, Sun 15 Nov)

Verdict: 3rd at best, 6.0/10. Scores: demo 6, user need 6, controls 7, exceptions 5.5, openness 5.
Official weights: end-to-end demo 30%, user need 20%, autonomy and controls 20%, exceptions 15%, openness and path to production 15%.

What was wrong, most damaging first:
1. The official milk example failed in Ask Valio and over MCP. No MCP tool to order a product by code and quantity.
2. The portal's own example "Conference lunch Tuesday, 60 guests, one vegan option" and off-menu dishes only got a question.
3. Weekly limit checked per order; monthly limit never enforced; the same week orderable three times.
4. Bell said "Within your rules" for an order EUR 1,330 over the limit. Approvals and rule changes not logged. Receipt showed old check times and "recent prices".
5. Confirmation said "Order sent to Valio" above small print saying no real order was placed.
6. "Lemon tart with almond crust" in a no-nut kitchen: no warning. "Kolme vierasta on maidoton" ignored. A nut-allergy note only got a question.
7. MCP had no authentication; a stranger's order appeared. About 4 in 10 calls returned 403.
8. Portal and MCP gave different orders for the same wedding.
9. Each approve or +/- took 5 to 6 s and returned 430 KB; quantities could not be typed.
10. Stale panel from the previous request; real error hidden behind the drawer; repeating a request said "Added 0 products".
11. Catalogue: greyed rows with no reason, wrong pack display, milk chocolate first for "lactose-free milk", no add feedback, wrong delivery day.
12. Details: "412 bookings", "kg/L", raw dates, mixed euro formats, "Saturday haat", flat invoice, no allergen removal, bare sign-in page.
